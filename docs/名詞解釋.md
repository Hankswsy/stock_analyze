# K 線組合辨識 — 名詞解釋

這份文件整理本專案(K 線組合無監督辨識)用到的所有名詞,依主題分組,白話解釋。
搭配程式模組閱讀:`kline/data.py`、`features.py`、`discover.py`、`analyze.py`、`visualize.py`。

---

## 一、K 線本身

| 名詞 | 白話解釋 |
|------|---------|
| **OHLCV** | 一根 K 線的五個數字:**O**pen 開盤價、**H**igh 最高、**L**ow 最低、**C**lose 收盤、**V**olume 成交量 |
| **實體(body)** | K 線中間那個粗方塊,是開盤到收盤的範圍。實體大 = 當天漲跌幅大 |
| **上/下影線(shadow)** | 實體上下的細線。上影線 = 盤中衝高但收回來;下影線 = 盤中殺低但拉回來。影線反映「被拒絕的價格」 |
| **gap(跳空)** | 今天開盤價 ≠ 昨天收盤價,中間跳了一段。常見於重大消息後 |
| **還原權值 / 除權息** | 公司配息時股價會「除息」往下跳一格,那不是真跌。`auto_adjust=True` 幫我們把歷史價格調整過,消掉這種假跌,不然會被誤認成型態 |

---

## 二、機器學習基本框架

| 名詞 | 白話解釋 |
|------|---------|
| **特徵(feature)** | 餵給模型的數字。我們把每根 K 線變成「實體多大、影線多長」這些數字,就是特徵 |
| **特徵向量** | 一個視窗(5 根 K 線)轉出來的一整排數字,共 25 個 → 一個 25 維向量 |
| **特徵矩陣** | 把所有視窗的向量疊起來的大表格。`(12110, 25)` = 12110 個視窗 × 每個 25 個數字 |
| **維度(dimension)** | 就是「有幾個數字」。25 維 = 每個樣本用 25 個數字描述 |
| **監督式 vs 無監督** | **監督**:先給答案(這是晨星、那是吞噬),模型學著分類。**無監督**:不給答案,讓模型自己把長得像的歸成一堆。本專案走無監督 |
| **label(標記/答案)** | 監督式需要的「正確答案」。無監督沒有 label |
| **過擬合(overfitting)** | 模型把「單一股票的巧合」當成通則背下來,換一檔就失效。多檔混合訓練就是為了避免這個 |

## 三、把 K 線變成特徵(`features.py`)

| 名詞 | 白話解釋 |
|------|---------|
| **滑動視窗(sliding window)** | 像一個 5 格的框,從頭到尾一格一格往右滑,每個位置框住連續 5 根 K 線當一個「組合」樣本 |
| **正規化(normalize)** | 把數字縮放到統一範圍,好比較 |
| **min-max 正規化** | `(x - 最低) / (最高 - 最低)`,把價格壓到 0~1。價格用這個 |
| **z-score 正規化** | `(x - 平均) / 標準差`,看「偏離平均幾個標準差」。成交量用這個(量沒有天然上限) |
| **尺度不變(scale-invariant)** | 正規化後,2330 的 1000 元和小型股的 15 元,只要形狀一樣,數字就一樣。這是多檔能混合的前提——比的是形狀不是價位 |

---

## 四、分群找型態(`discover.py`)

| 名詞 | 白話解釋 |
|------|---------|
| **分群(clustering)** | 把長得像的樣本自動歸成一堆一堆。無監督的核心動作 |
| **KMeans** | 最常用的分群法。你說「分成 k 堆」,它找出 k 個中心,把每個樣本歸到最近的中心 |
| **群心(centroid)** | 每一堆的「平均中心」,是算出來的抽象點,不一定對應真實樣本 |
| **medoid** | 每一堆裡「離中心最近的真實樣本」。畫圖用它,因為它是真的發生過的 K 線,比抽象群心像樣 |
| **標準化(StandardScaler)** | 分群前先把每個特徵拉到同一尺度,免得數值大的特徵(如量)霸佔距離計算 |
| **PCA(主成分分析)/ 降維** | 25 維裡很多資訊重複又有雜訊。PCA 壓成更少維、但保留主要資訊(設保留 95%),去雜訊 + 加速 |
| **變異(variance)** | 資料的「資訊量/分散程度」。保留 95% 變異 = 留住 95% 資訊,丟掉最沒用的 5% |
| **silhouette(輪廓分數)** | 打分數看「分得好不好」:群內夠緊、群間夠開就高分。用它在 k=4~12 間自動挑最佳 k。分數 0~1,金融資料到 0.15 左右已算正常(型態本來就沒明顯邊界) |

## 五、判斷型態有沒有用(`analyze.py`)

| 名詞 | 白話解釋 |
|------|---------|
| **未來報酬(forward return)** | 型態出現後,過幾天股價漲跌了多少。`= 之後的收盤 / 現在收盤 − 1` |
| **horizon(展望期)** | 「往後看幾根」。horizon=5 = 看 5 個交易日後的報酬 |
| **勝率(win rate)** | 這型態出現後,上漲的比例。0.55 = 55% 的時候會漲 |
| **平均/中位數報酬** | 平均 = 算術平均(易被極端值拉動);中位數 = 排中間那個(較穩健)。一起看能判斷是不是尾部效應 |
| **標準差(std)** | 報酬有多「忽上忽下」。越大代表越不穩、越不可靠 |
| **signal_t(訊號強度 / 類 t 值)** | `平均報酬 / 標準差 × √樣本數`。綜合「報酬夠大 + 夠穩 + 樣本夠多」。慣例 **\|t\| > 2 才算統計顯著**(不太可能是運氣) |
| **統計顯著** | 「這結果不太可能是碰運氣來的」。用 t 值判斷 |
| **n_syms / breadth(普遍性)** | `n_syms` = 這型態涵蓋幾檔股票;`breadth` = 在多少比例的股票上有效。breadth 高 = 跨股票通用,不是單一檔巧合 |

## 六、去市場化

| 名詞 | 白話解釋 |
|------|---------|
| **beta(貝它)** | 一檔股票對大盤的「敏感度」。beta=1 = 跟大盤同步;beta=1.5 = 大盤漲 1%,它平均漲 1.5%。權值股 beta 常 >1 |
| **alpha(阿爾法)** | 扣掉大盤影響後,額外賺到的報酬。真正代表「這型態本身的功力」 |
| **市場中性 / 去市場化** | 把「大家一起漲」的大盤成分減掉,只留 alpha。公式:`個股報酬 − beta × 大盤報酬` |
| **為什麼要做** | 未去市場化時 signal_t 看似很高,其實多半是大盤在漲的 beta。去市場化後才看出型態本身的真實 alpha |

## 七、資料處理與驗證

| 名詞 | 白話解釋 |
|------|---------|
| **reindex** | 把一個序列「對齊」到另一組日期上。用它把大盤(0050)對到每檔股票的日期軸,避免停牌日錯位 |
| **ffill(前向填補)** | 對齊後某天剛好沒值,就用前一個有效值補上 |
| **未來函數偏誤 / lookahead bias** | 不小心用到「當下還不知道的未來資訊」,讓回測虛假變好。實戰前必須排除 |
| **walk-forward** | 正確的驗證法:只用過去資料建模型,測未來沒看過的資料,一段段往前滾。模擬真實交易 |

## 附:一句話資料流

```
股票代碼
  → data.py       下載 OHLCV(還原權值)
  → features.py   滑動視窗 + 尺度不變正規化 → 特徵矩陣
  → discover.py   標準化 → PCA → KMeans 分群 → labels
  → analyze.py    各自股票序列上算未來報酬 / 去市場化超額報酬
  → visualize.py  每群 medoid 畫成 K 線圖 → patterns.png
```
